## What it catches

the ONE-COMMAND self-host path from a fresh clone (card `t_28a06494`), offline: a stubbed `docker` on PATH records every invocation, so "did it start anything" is read off a log, and stdin is not a tty so the interactive prompt cannot fire by accident. It asserts the REFUSAL in both directions, because this is the failure that is silent everywhere: a stack that comes up with `ENCRYPTION_KEY` = a default the repository publishes is healthy, serves traffic, and is readable by anyone who has read the repo. Refused, NAMED and left on disk BYTE-IDENTICAL (a bootstrap that half-writes a file is how the next run adopts it as "the operator's"): a placeholder `ENCRYPTION_KEY` (both the shape this repo's compose used to default to and the one the env template ships), a 63-char key, a 64-char NON-hex key, a placeholder `APP_BASE_URL`, placeholder `POSTGRES_PASSWORD`/`S3_SECRET_KEY` — and a first run with no `--base-url` writes no file at all. Started, because a guard that refuses everything is an outage: a clean run generates all three secrets with `openssl rand -hex 32` (asserted 64 hex chars each, and two fresh runs produce DIFFERENT keys, which is what rules out a generator that emits a constant), the file is `0600`, and the front door is DERIVED from the origin — `https://` → `APP_ENV=prod` + 443/80, `http://host:port` → `APP_ENV=dev` (a `Secure` cookie is never returned over plain HTTP, so an http deployment claiming prod would log in and then forget the session) with the origin's port as the published one and the site address carrying no port (Caddy listens on 80/443 inside its container). A SECOND run adopts the file and must leave every secret byte-identical: rotating `ENCRYPTION_KEY` silently orphans every stored payment credential. The compose is pinned as a complete stack — `web` present (the pre-self-host file had api+pg+valkey+minio and NO web, so a stranger could get an API and no product), exactly two published host ports (Caddy's), no `ports:` on api/postgres/valkey/s3, `restart: unless-stopped` and a healthcheck on each of the six long-running services (the S3 service is SeaweedFS, pinned by tag: the `minio/minio` and `minio/mc` images were withdrawn from Docker Hub, so a compose that names them cannot be pulled at all), NO one-shot bucket container at all (the API creates its own bucket, so there is nothing to run once), `api` waiting on `s3: service_healthy`, the web image built from the repo root, and NO working default secret on any of them — read from CODE with comments stripped, because the file's own header records the default that was removed. Then the real validator, `docker compose config` (parse+interpolate, no daemon) with a generated env file: exit 0, no warning on stderr, and no environment value interpolating to null; a missing docker is a FAILURE, never a skip. The Caddyfile's path split is asserted on BOTH sides — `/f/` `/t/` `/v1/` `/media/` `/embed/` `/oauth/` `/.well-known/oauth-*` `/healthz` → `api:8080`, everything else INCLUDING `/api/` → `web:3000` (that `/api/` case is the dashboard's same-origin proxy and is what keeps the session cookie first-party), and the file is mounted `:ro`. Finally the install path (`deploy/selfhost/`, the compose, the env template, `docs/SELF-HOST.md`, `README.md`) is grepped for OUR hosts and carries none of them. BITE-PROVED on this tree: re-introducing `ENCRYPTION_KEY:-dev_only_…` in the compose reds 2 checks, neutering the fail-closed `if` reds 6 (including the file-mutation and the docker-log arms), and dropping `/f/*` from the front door reds 1.
